## 2. スコープ

対象範囲は動画編集ツール一式 + インサイト機能。

| 画面/機能 | パス | 概要 |
|---|---|---|
| アップロード | `/create` | 動画ファイルをアップロードし、使用範囲の起点を作る |
| ラフカット | `/create/cut` | 不要な部分を先に切り捨て、以降の処理対象を絞り込む |
| 参考画像/動画・字幕生成 | `/create/style` | Geminiでスタイル抽出・文字起こしを行う(任意/非同期) |
| クリップ編集 | `/edit` | クリップ・スタイル・音声(SE/BGM/AIナレーション)を編集する本体 |
| 書き出し | `/edit/export` | Remotionでの動画レンダリングとダウンロード |
| クチコミ閲覧 | `/insights` | Google Places APIで店舗の評価・クチコミを見る(動画編集とは独立、導線は非表示) |

対象外(今回のスコープに含めない): 新機能追加、UIデザインの刷新、DB導入、認証機能、
マイクロサービス化(方針として明示的に対象外)。

## 3. 主要ユーザーフロー(現状の正として扱う)

1. `/create` で動画をアップロード → 全体を1つの「使う範囲」として保存 → `/create/cut` へ。
2. `/create/cut` で分割・イン/アウト点・トリム・削除・並べ替えにより「使う範囲」を確定。
   ここで捨てた範囲は以降のスタイル抽出・字幕生成の対象外になる。
3. `/create/style` で(任意)参考画像/動画からスタイルを抽出し、「音声から字幕を生成」を実行。
   非同期ジョブの進捗をポーリングで表示。スキップも可能。
4. `/edit` でクリップ(トリム・分割・並べ替え・字幕・演出・音量)、スタイル(配色・フォント・
   位置・サイズ・フェード)、音声(SE・BGM・AIナレーション)を編集。操作毎に自動保存。
5. `/edit/export` で書き出しジョブを開始し、進捗・残り時間の目安をポーリングで表示、
   完成した動画のURLを取得する。

独立フロー: `/insights` で店名・住所を検索し、評価・直近クチコミ(最大5件)を表示する。

## 4. 機能要件(壊してはいけない既存機能一覧)

S4(実装)・S5(レビュー)・S7(テスト)は、少なくとも以下がリグレッションしていないことを
確認する。

### 4.1 アップロード・カット
- [ ] 動画アップロード(`/api/upload`、拡張子: mp4/mov/webm/m4v、上限200MB)
- [ ] 動画の長さのブラウザ側自動検出、失敗時の再試行導線(Safari/iOS対策)
- [ ] 分割(`S`)・イン/アウト点(`I`/`O`)・トリム・削除・並べ替え
- [ ] カットで捨てた範囲がスタイル抽出・字幕生成の対象から除外される

### 4.2 スタイル抽出・字幕生成
- [ ] 参考画像からのスタイル抽出(`/api/extract-style`、PNG/JPEG/WebP、上限10MB)
- [ ] 参考動画からのスタイル抽出(`/api/extract-style-from-video`、Gemini File API経由)
- [ ] 文字起こし(`/api/transcribe-captions`)、進捗表示(アップロード中→処理中→生成中→完了)
- [ ] 文字起こし結果がカットで選んだ範囲だけに切り詰められる(`clipTranscribedToKeepRanges`)
- [ ] 字幕生成をスキップして編集へ進む導線

### 4.3 クリップ編集(`/edit`、6タブ)
- [ ] クリップ: トリミング・分割・追加/削除/複製/結合・並べ替え・複数選択・
      字幕の個別/一括編集・クリップ毎の音量(ミュートチェック含む)・テロップ出現演出(9種)・
      Undo/Redo
- [ ] スタイル: プリセット(6種)一括適用、配色、テロップ見た目(pill/outline)、
      フォント(15書体)、テロップ位置、文字サイズ、全体フェードイン/アウト
- [ ] SE: プリセット10種 or アップロード、最大30個(`/api/upload-audio`、上限20MB)
- [ ] BGM: 音量・フェードイン/アウト・ループ再生
- [ ] AIナレーション: クリップ単位/全クリップ一括生成(`/api/generate-voiceover`)、
      生成失敗時のリトライ(原因不明のエラー含め全種類が対象)
- [ ] 操作毎の自動保存、リロード/再訪問時の復元
- [ ] プロジェクトのJSONエクスポート/インポート

### 4.4 書き出し
- [ ] 書き出しジョブの開始・進捗ポーリング・残り時間の目安・完成動画URL取得
      (`/api/render`)
- [ ] レンダー失敗時の1回自動リトライ
- [ ] `/api/media/[...path]` でのRange対応配信(iOSの「ビデオを保存」・シークに必要)

### 4.5 インサイト(`/insights`)
- [ ] 店名・住所での場所検索(`/api/insights/search-place`)
- [ ] 評価・直近クチコミ(最大5件)の取得(`/api/insights/place-details/[placeId]`)

## 6. 制約条件

- Next.js 16(App Router)、React 19、TypeScript(strict)、Tailwind CSS v4、Remotion 4、
  `@google/genai`、zodのバージョン・構成を維持する(メジャーバージョンアップはスコープ外)。
- `serverExternalPackages: ["@remotion/bundler", "@remotion/renderer"]`(`next.config.ts`)は
  ネイティブバイナリ解決のために必須。変更する場合はデプロイ動作確認が必須。
- パスエイリアス `@/* → src/*`、`@video/* → remotion/*` を維持する。

## 7. 自動テスト基盤の現状(確認結果)

**確認結果: 自動テスト基盤は一切存在しない。**

- `package.json` に `test` スクリプトは無い。`jest` / `vitest` / `playwright` / `cypress` /
  `@testing-library/*` のいずれも依存関係に含まれない。
- リポジトリ内に `*.test.*` / `*.spec.*` ファイル、`__tests__` / `tests` / `e2e` ディレクトリは
  存在しない(`find`で0件)。
- 品質担保の現状の手段は ESLint(`eslint-config-next`、`next lint`)と TypeScript の
  `strict`型チェックのみ。

**S7(テスト計画・実施)への申し送り**: 自動テストが無いため、qa-expertペルソナには
「テスト計画の作成」と「実行可能な範囲の手動確認手順の明文化」を主成果として依頼する。
実装差分(S4)の規模によっては、影響範囲に限定した最小限の自動テスト導入(例: 純粋関数
`timelineUtils.ts` / `duration.ts` 等のユニットテスト)をS3の実装計画に含めるかどうかを
S2/S3で判断する。
